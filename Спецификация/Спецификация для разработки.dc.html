Спецификация для разработки

Справочник пациентов и создание медкарты

Инструкция для ИИ-ассистента. Это функциональное ТЗ без кода. Реализуй поведение строго по правилам ниже. Если правило не описано — не придумывай, а задай вопрос. Все тексты интерфейса указаны точно, используй их дословно. Букву «ё» не используем.

0. Глоссарий

  • Сеть клиник — все клиники компании.
  • Город — у города либо несколько организаций, либо город сам является одной клиникой (hasOrgs = false).
  • Организация — клиника, в которой оформляется медкарта.
  • Пациент — один на всю сеть. Поля: фамилия, имя, отчество, дата рождения, телефон, email, пол, гражданство, социальный статус, адрес, паспорт, СНИЛС, полис ОМС.
  • Медкарта — принадлежит пациенту и организации, имеет номер. У пациента не больше одной медкарты в организации.
  • Область — выбранные город и организация (или все доступные организации города).
  • Доступные организации — организации, к которым у пользователя есть права.

2. Экран «Справочник пациентов»

Слева панель фильтров (280px), справа рабочая область со списком. Правая панель пациента выезжает поверх контента.

2.1 Фильтры

Состояние: draft (выбрано в полях) и applied (по чему построен список).

  • Город — Autocomplete, обязательный, опции = доступные города по алфавиту. При смене: draft.org = ''.
  • Организация — Autocomplete, необязательный. Опции = доступные организации выбранного города. disabled, если город не выбран. Не отображается, если у города hasOrgs = false.
  • Сформировать — primary, accent, во всю ширину. Видима, только если draft ≠ applied и город заполнен. По нажатию: applied = draft, прокрутка в начало, загрузка списка.
  • Сбросить фильтры — secondary, neutral. Видима, если draft ≠ исходные фильтры роли. По нажатию draft = исходные (список не перестраивается).

Состав списка: пациенты, у которых есть хотя бы одна медкарта в области:

  • выбрана организация → медкарта в этой организации;
  • выбран только город → медкарта в любой доступной организации этого города.

2.2 Шапка рабочей области

Показывается, только если applied.city заполнен.

  • Поле поиска — placeholder «Поиск пациента (ФИО, номер телефона)», с кнопкой очистки.
  • Добавить пациента — primary, accent → экран создания пациента.
  • Пациенты (N) — когда список загружен. N = число пациентов в области; при поиске — число найденных в области.
  • Подпись справа: запрос короткий — «Для поиска введите минимум 3 буквы ФИО или 4 цифры телефона»; идет поиск — «Ищем в текущем списке и в сети клиник…».

2.3 Правила поиска

  • Запрос телефонный, если состоит только из цифр, пробелов, + ( ) -. Минимум 4 цифры. Ведущая 8 в 11-значном номере заменяется на 7. Совпадение — номер пациента содержит введенные цифры.
  • Иначе запрос по ФИО. Минимум 3 буквы без пробелов. Нормализация: trim, нижний регистр, ё → е. Разбить на слова. Совпадение, если каждое слово — начало соответствующего слова ФИО по порядку (Фамилия Имя Отчество) или каждое слово — начало любого слова ФИО.
  • Debounce 300 мс.
  • Пустой запрос → полный список.
  • Поиск идет одновременно: 1) в текущем списке (пациенты области); 2) по сети — все пациенты сети вне области, независимо от прав пользователя.

2.4 Таблица

Колонки: ФИО 300px, Дата рождения 112px (ДД.ММ.ГГГГ), Телефон 156px (пусто → «—»), Медкарты 280px. Заголовок прилипает при прокрутке. Сортировка по ФИО (русская локаль).

Колонка «Медкарты»:

  • выбрана организация → только «№ номер» карты в этой организации;
  • выбран только город → «№ номер» + название организации (вторичный цвет), карты этого города, сортировка по организации;
  • максимум 2 карты; если больше — ссылка (акцентный цвет) «Еще N карта/карты/карт», клик открывает правую панель (не всплывает к строке);
  • карт нет → «—».

Пагинация: бесконечная прокрутка порциями по 40, подгрузка за 240px до конца, строка «Загружаем еще…». Загрузка: скелетон из 8 строк.

Строки: заливки table-bg-table-row-default / hover / pressed, строка открытого пациента — table-bg-table-row-selected-*. Клик по строке — открыть/закрыть панель (раздел 3).

2.5 Результаты поиска

  • Совпадения в области — в основной таблице.
  • В области пусто, но есть в сети → строка «В текущем списке совпадений нет».
  • Блок «Найдены в сети клиник (N)», если есть совпадения в сети. Подпись: город выбран — «Есть в базе сети, но без медкарты в текущей области»; иначе — «Пациенты всей сети клиник»; если найдено больше 20 — дописать «. Показаны первые 20 — уточните запрос».
  • Таблица блока: те же колонки + колонка 160px с кнопкой «Создать медкарту» (outline, accent, s). Медкарты: «Город · Организация» или «Город» при hasOrgs = false; сортировка по городу, затем организации; максимум 2 + «Еще N карт».
  • «Создать медкарту» disabled, если у пациента карты во всех доступных организациях; тултип «У пациента есть медкарты во всех доступных вам организациях». Клик не открывает панель, открывает модалку создания медкарты (раздел 5).

3. Правая панель пациента

Плавающая панель справа, ширина 600px, отступ 16px от краев, анимация выезда.

Открытие: клик по строке основной таблицы, блока сети, по карточке совпадения в форме создания, по ссылке «Еще N карт».

Закрытие: крестик; Esc (если не открыта модалка); повторный клик по строке того же пациента. Клик по другому пациенту — панель остается, данные меняются.

Содержимое:

  1. Шапка: ФИО (20/26, semibold), ниже «ДД.ММ.ГГГГ (N лет)».
  2. Желтый алерт «Нет медкарты в выбранной области» — если панель открыта из справочника, город в фильтрах выбран и у пациента нет медкарты в области.
  3. Группы данных (подпись сверху, значение снизу; пусто → «—»): Контактные данные — Номер телефона, Email, Адрес по прописке. Общая информация — Пол, Гражданство, Социальный статус, Дата регистрации. Документы — «Паспорт»: Серия, Номер, Дата выдачи, Код подразделения, Кем выдан; «Другие документы»: СНИЛС, Полис ОМС.
  4. Разделитель.
  5. Медицинские карты (N): «Город · Организация» (или «Город» при hasOrgs = false) слева, «№ номер» справа, сортировка по алфавиту. Карт нет → «У пациента пока нет медкарт».

Режимы:

  • Из справочника: в заголовке блока медкарт кнопка «Создать медкарту» (ghost, accent, s). disabled, если нет свободных доступных организаций; тултип «У пациента есть медкарты во всех доступных вам организациях».
  • Из формы создания: кнопки «Создать медкарту» нет, внизу кнопка «Выбрать пациента» (primary, accent) — действие из 4.6.

4. Создание пациента

Отдельный экран. Хлебные крошки: «Справочник пациентов» (кликабельно) / «Создание пациента» (акцентный цвет). Карточка формы максимум 900px по центру.

Заголовок «Создание пациента», подзаголовок «Пациент создается один раз для всей сети клиник. Медицинские карты оформляются отдельно для каждой организации.»

Шаги «Основные данные» и «Дополнительные данные», между ними линия.

4.2 Шаг 1 — Основные данные

Заголовок «Основные данные», подпись «Укажите данные пациента. При нажатии «Продолжить» мы проверим, есть ли он в сети клиник.»

Ошибки Фамилии, Имени, Отчества, Даты рождения — сразу при вводе; остальные — после первого нажатия «Продолжить».

Кнопки справа: «Отмена» (secondary, neutral) → выход (4.8); «Продолжить» (primary, accent).

4.3 Проверка шага 1 (по «Продолжить»)

  1. Есть ошибки полей шага 1 → toast «Проверьте заполнение полей», стоп.
  2. Проверка по этим же данным уже выполнена с результатом none или possible → сразу шаг 2.
  3. Иначе: кнопка loading, запрос проверки.
  4. Ошибка проверки → модалка 4.9.
  5. Для каждого пациента сети: ФИО — фамилия и имя совпадают, отчество совпадает, если указано у обоих (пустое у одного не мешает), сравнение после нормализации (trim, нижний регистр, ё → е); Дата рождения — равенство; Телефон — введен полностью (11 цифр) и совпадает.
  6. Результат: есть ФИО + ДР + телефон → exact (показать только таких); иначе есть (ФИО + ДР), (ФИО + телефон) или (только телефон) → possible (показать всех); иначе → none, переход на шаг 2.

possible: желтый алерт (warning, иконка WarningAmber) — «Найдены похожие пациенты» / «В сети клиник найдены пациенты с похожими данными. Если нужного пациента нет в списке, нажмите «Продолжить» еще раз.» Список карточек (4.6), «Выбрать пациента» — outline, neutral. Повторное «Продолжить» с теми же данными → шаг 2.

exact: красный алерт (error, иконка ErrorOutline) — «Пациент уже есть в системе» / «Создать нового пациента нельзя. Выберите пациента из списка или проверьте введенные данные». Список карточек, «Выбрать пациента» — primary, accent. «Продолжить» disabled.

Если после possible изменены ФИО, ДР или телефон — алерт и список скрыть, показать серую плашку (info) «Данные изменились. При нажатии «Продолжить» проверка выполнится заново.» После exact — алерт скрыть, «Продолжить» снова активна.

4.4 Шаг 2 — Дополнительные данные

Сверху сводка (Basic data summary, фон bg-surface-level-2): «ФИО · ДД.ММ.ГГГГ (N лет) · телефон» (если указан) и «Изменить» (ghost, accent, s) → шаг 1.

  • Личные данные (3 колонки): Пол* (Select: Мужской / Женский; «Укажите пол»), Гражданство (Autocomplete: Российская Федерация, Беларусь, Казахстан, Киргизия, Узбекистан, Таджикистан, Армения, Азербайджан, Другое), Социальный статус (Select: Работающий, Неработающий, Пенсионер, Студент, Учащийся, Ребенок дошкольного возраста).
  • Контактные данные: Адрес по прописке.
  • Документы → Паспорт (4 колонки): Серия (4 цифры, «Серия — 4 цифры»; если указан только номер — «Укажите серию»), Номер (6 цифр, «Номер — 6 цифр» / «Укажите номер»), Дата выдачи (не в будущем; не раньше ДР — «Раньше даты рождения»), Код подразделения (000-000, «Формат 000-000»), Кем выдан (во всю ширину).
  • Документы → Другие документы: СНИЛС (000-000-000 00, «СНИЛС — 11 цифр»), Полис ОМС (16 цифр, «Полис ОМС — 16 цифр»).

Ошибки шага 2 — после первого нажатия «Создать пациента».

Кнопки: «Назад» (secondary, neutral) → шаг 1; «Создать пациента» (primary, accent) — disabled, если не выбран пол или результат проверки hard.

4.5 Проверка шага 2 (по «Создать пациента»)

  1. Есть ошибки → toast «Проверьте заполнение полей». Ошибка в полях шага 1 — вернуть на шаг 1. Стоп.
  2. Loading на кнопке, запрос проверки. Ошибка → модалка 4.9.
  3. Для каждого пациента сети: hard — совпал паспорт (серия + номер, 10 цифр), СНИЛС (11 цифр) или полис ОМС (16 цифр); soft — совпало ФИО и (ДР или телефон), при этом не противоречат пол (указан у обоих и разный — не soft) и документы (заполнены у обоих полностью и различаются — не soft); совпали только телефон или только ДР — не учитывать.
  4. Результат: есть hard → красный алерт с текстом из 4.3 exact, список карточек (primary, accent), создание заблокировано; есть soft и среди них есть пациенты, которых пользователь еще не видел для этих данных → желтый алерт «Найдены похожие пациенты» / «В сети клиник найдены пациенты с похожими данными. Если нужного пациента нет в списке, нажмите «Создать пациента» еще раз.», кнопки outline, neutral; иначе → создать пациента (4.7).
  5. При изменении данных после алерта — серая плашка «Данные изменились. При нажатии «Создать пациента» проверка выполнится заново.»

Пример «Смена фамилии»: фамилия новая, имя, отчество, ДР и паспорт совпадают → на шаге 1 совпадений нет, на шаге 2 — hard.

4.6 Карточка совпадения (Matched patient card)

Список карточек в рамке (border, radius 12), между карточками разделитель.

  • Строка 1: ФИО (500) · ДД.ММ.ГГГГ · телефон (что есть).
  • Строка 2: «Совпадения: » (вторичный цвет) + совпавшие поля через запятую, первое с заглавной: «ФИО» (или по отдельности «фамилия», «имя», «отчество», если ФИО целиком не совпало), «дата рождения», «телефон», «паспорт», «СНИЛС», «полис ОМС».
  • Справа кнопка «Выбрать пациента» (size s).

Клик по карточке → открыть/закрыть панель пациента (режим «из формы»), карточка подсвечивается как selected.

«Выбрать пациента» (в карточке или в панели): сбросить форму, перейти в справочник, открыть панель выбранного пациента, toast «Открыт существующий пациент. Новый пациент не создан».

4.7 После создания

  • Пациент создается без медкарт.
  • Переход в справочник, открыта панель нового пациента.
  • Модалка (size s) «Создать медкарту?» / «Пациент успешно создан. Хотите создать ему медицинскую карту?»: «Не сейчас» (secondary) → toast «Пациент сохранен без медкарты»; «Создать медкарту» (primary, accent) → модалка из раздела 5.

4.8 Выход из формы

Триггеры: «Отмена» на шаге 1, клик по «Справочник пациентов» в крошках. Если что-то введено — модалка «Выйти без сохранения?» / «Введенные данные пациента будут потеряны», кнопки «Отменить» / «Выйти» (primary, accent). Иначе выход сразу.

4.9 Ошибка проверки

Модалка (size s) «Не удалось проверить пациента» / «Проверка не выполнена из-за ошибки соединения. Повторите попытку еще раз», кнопки «Отменить» / «Повторить» (повторяет проверку текущего шага).

5. Создание медкарты (модалка)

ActionModal size m, заголовок «Создание медкарты», крестик.

Точки входа: кнопка в панели пациента, кнопка в блоке «Найдены в сети клиник», модалка после создания пациента, кнопка «Создать в другой организации».

  • «Пациент: ФИО».
  • Город* (Autocomplete, доступные города по алфавиту).
  • Организация* (Autocomplete, доступные организации города). disabled, пока не выбран город. Не показывается, если в городе одна доступная организация.

Предзаполнение:

  • Город выбран в фильтрах и доступен → подставить; организация из фильтров доступна и свободна → подставить; организация не выбрана, а в городе одна свободная → подставить ее.
  • Фильтры пустые: у пользователя одна доступная организация → подставить город и организацию (если свободна); один доступный город → подставить его и, если там одна свободная организация, ее.

При смене города организация сбрасывается; если в новом городе одна свободная организация — подставить ее.

Занятые организации (у пациента уже есть медкарта): пункт disabled, текст «Название (медкарта № N)», тултип «У пациента уже есть медкарта в этой организации».

Алерты (желтые): все организации выбранного города заняты → «У пациента уже есть медкарта в этом городе»; иначе нет свободных доступных организаций → «У пациента уже есть медкарты во всех доступных вам организациях».

Кнопки: «Отмена» (secondary, neutral), «Создать медкарту» (primary, accent) — активна, если выбраны город и свободная доступная организация. Во время запроса: loading, поля и «Отмена» disabled, модалку нельзя закрыть.

Результат:

  • Успех → закрыть модалку, присвоить номер, toast «Медкарта № N создана · Организация». В справочнике — открыть панель пациента, обновить списки.
  • Конфликт (карту в этой организации за это время создал другой сотрудник) → закрыть модалку, открыть модалку (size s) «Медкарта уже создана» / «Другой сотрудник создал медкарту № N в организации «Организация» (Город) раньше вас» (для города без организаций — «в городе Город»). Кнопки: «Создать в другой организации» (secondary, только если остались свободные; открывает модалку создания медкарты) и «Понятно» (primary, accent).

6. Общие элементы

  • Toast: внизу по центру, темный фон, исчезает через ~3 секунды.
  • Тултипы: темный фон, 12px, у неактивных кнопок и пунктов списка.
  • Алерты (Duplicate check alert и др.): Warning — bg-system-warning-light, иконка WarningAmber foreground-system-warning; Error — bg-system-error-light, иконка ErrorOutline foreground-system-error. Радиус 12.
  • Цвета — семантические токены дизайн-системы Asya. Компоненты — @asya/web-design (Button, Autocomplete, Select, TextField, DatePicker, SearchField, IconButton, ActionModal).
  • Склонения: «год / года / лет», «карта / карты / карт».

7. Что в прототипе условно (уточнить на бэкенде)

  • Пороги поиска (3 буквы, 4 цифры, 300 мс) и правила совпадений — демонстрационные.
  • Поиск по сети охватывает всех пациентов независимо от прав; в панели видны все медкарты пациента — подтвердить с безопасностью.
  • В блоке сети показывается до 20 записей.
  • Проверки на дубли выполняются на сервере; список совпавших полей возвращает сервер.
